# Эвалы и тест-кейсы core loop Narra

Статус на 2 сентября 2026. Матрица из 57 кейсов по шести областям, которые задал пользователь, плюс релизный чек-лист. Колонка «Покрытие» — что реально существует в репозитории сейчас; «план» — как автоматизировать (см. также раздел «Харнесс»).

Легенда типов: unit — vitest/node:test без сети; contract — проверка формы данных/маршрутов; integration — реальные модули (foliate/WebKit, gateway с фикстурами); live-llm — против `api-test` с тестовой установкой и LLM-судьёй; manual-simulator — ручной сценарий в симуляторе.

## Запуск и CI
- Локально: `pnpm --filter @readany/app-expo test && pnpm --filter @readany/app-expo test:evals`, `pnpm test:core`, `cd services/narra-gateway && npm test && npm run test:evals`, `pnpm --filter @readany/app-expo test:reader:e2e`, `pnpm --filter @readany/narra-evals run all --max-usd 10`.
- Новый workflow `.github/workflows/app-expo.yml` (PR/push по `packages/app-expo/**`, `packages/core/**`, `packages/foliate-js/**`, `packages/deslop-primitives/**`): pnpm install, `tsc --noEmit -p packages/app-expo`, `biome check`, `pnpm test:core`, `pnpm --filter @readany/app-expo test`, `test:evals`; отдельный job `reader-e2e` с `npx playwright install webkit` и `test:reader:e2e` (артефакт — скриншоты).
- Расширить narra-gateway.yml шагом `npm run test:evals` (только replay-фикстуры, без сети).
- Новый workflow `live-evals.yml`: `workflow_dispatch` + `schedule` (ночью, будни), secrets `NARRA_EVAL_INSTALLATION_ID/SECRET`, `NARRA_EVAL_JUDGE_API_KEY`; `--max-usd 10`; артефакт reports/; job падает при hard-fail-rate выше порога, при мягком падении — только предупреждение и комментарий в Issue «Narra evals».
- Контроль стоимости: CLI останавливается при достижении `--max-usd` (оценка по токенам ответа судьи и фиксированным ценам в `src/pricing.json`), детерминированный сэмплинг по `--seed`, кэш ответов гейтвея по `request_hash` в `reports/.cache` (повторный прогон судьи на тех же ответах бесплатен для гейтвея), генерация сцен/портретов только в suite `scene-vision --generate` (по умолчанию оценивает уже опубликованные медиа из манифеста). Ежедневные лимиты гейтвея на установку (aiDailyLimit/imageDailyLimit, index.mjs:1748,2110) — для евалов завести отдельную установку, чтобы не сжигать квоту тестировщиков.

## Правила
- Дизайн-система @deslop/primitives не трогается; UI-копии в тестах — русские строки из i18n.
- Никаких туннелей; живые евалы ходят только на `https://api-test.narra.disrupt.builders` (или `NARRA_EVAL_GATEWAY_URL`).
- Фикстуры с api-test обезличиваются (без installation id, без токенов, без ссылок на объектное хранилище с подписями).

## Аутентификация (tools/narra-evals/src/auth.mjs)
Повторяет narra-gateway-fetch.ts:173-184 и :318-361:
1. Идентичность: `installation_id = crypto.randomUUID()`, `installation_secret = base64url(randomBytes(32))` — сохраняется в `tools/narra-evals/.state/installation.json` (gitignored) или берётся из `NARRA_EVAL_INSTALLATION_ID`/`NARRA_EVAL_INSTALLATION_SECRET` (CI secrets). Отдельная установка для евалов, чтобы не расходовать дневные лимиты (`aiDailyLimit`, `imageDailyLimit`, `speechDailyLimit` — index.mjs:1748,1950,2110) тестировщиков.
2. `POST /v2/installations/register` body `{installation_id, installation_secret, app_version:"narra-evals", platform:"ci", arch:"node"}` → `{token, token_type:"Bearer", expires_in}`; далее `POST /v2/installations/refresh` `{installation_id, installation_secret}`; 404 на refresh → register (fetch.ts:352); 401 на любом запросе → один refresh и повтор (fetch.ts:443). Регистрация под rate-limit (`registrationLimit`), поэтому токен кэшируется до `expires_in - 60 с`.
3. Все запросы: `authorization: Bearer <token>`, `content-type: application/json`. Тела чата: `origin:"background"`, `analytics_tier:"none"` (contracts.mjs:181-193) — чтобы евалы не попадали в продуктовую аналитику; `purpose` строго из PURPOSES.

## Рубрики судьи (промпты на русском, ответ строго JSON `{score:1..5, pass:bool, hard_fail:bool, reasons:[…]}`, temperature 0)
1. **Консистентность характера (CH-03/CH-12)** — вход: профиль (role, traits, speechStyle, description), реплика читателя, ответ. Критерии: (a) первое лицо и роль, (b) ≥1 черта проявлена, (c) манера речи соответствует speechStyle, (d) 1–3 предложения без списков/канцелярита, (e) реагирует на слова собеседника. hard_fail: «я ИИ/модель/персонаж книги», английский без запроса. pass = score ≥4 и !hard_fail.
2. **Нет знаний о современном мире (CH-04)** — вход: эпоха книги (год/автор), проба, ответ. 5: не знает/переспрашивает/толкует в терминах своей эпохи; 3: уклоняется без объяснения; 1: объясняет понятие или упоминает даты/имена после эпохи. hard_fail при объяснении сути современного предмета. Префильтр regex по словарю (смартфон|интернет|wi-?fi|биткоин|covid|ковид|Маск|соцсет|электромобил|самолёт для книг до 1900) + объяснительные конструкции.
3. **Спойлер-гард (CH-05)** — 5: уклонился в характере, вернул к известным событиям; 1: раскрыл судьбу/событие. Детерминированный hard_fail по именам поздних персонажей.
4. **Качество описания (CH-02)** — полнота (description ≥2 предложения, traits 3–8, speechStyle конкретен, greeting в характере), непротиворечивость (взаимоисключающие traits, description vs traits, gender vs имя), отсутствие внешности/должности среди traits (правило из internal-generation-service.mjs:1095). hard_fail — явное противоречие.
5. **Портрет (CH-10, vision)** — вход: картинка + паспорт (gender, age, appearancePrompt, эпоха, канон стиля). Чек-лист: ровно один человек; погрудно/анфас; пол и возраст; ключевые признаки внешности; одежда эпохи; нет текста/водяных знаков/рамок; стиль серии. hard_fail: >1 человека, текст, современная одежда, пустое/битое изображение.
6. **Сцена (SC-02/SC-03, vision)** — вход: excerpt, список героев с внешностью, жанровое арт-направление, 3 референса стиля. Критерии: перечисленные герои присутствуют (и никого лишнего), действие фрагмента, обстановка/эпоха, композиция без текста, стиль «та же серия одного художника». hard_fail: текст в кадре, ни одного героя, современные предметы в несовременной книге.
7. **Ассистент (NA-03/NA-04)** — язык интерфейса, опора на переданный контекст (цитаты существуют в chunks), нет выдуманных глав, соблюдение формата, спойлер-гард; для tool-кейсов — детерминированный ассерт наличия tool_call и совпадения цитаты с /search.
8. **Речь (AU-06)** — WER STT-транскрипта ≤0.15.

Калибровка: `calibration/<suite>.jsonl` — 20 вручную размеченных примеров на рубрику (владелец продукта + агент), команда `narra-evals calibrate` считает согласие судьи с метками; пороги считаются доверенными при agreement ≥0.8 (Cohen κ ≥0.6). Судья — одна модель, temperature 0, при сомнении (score 3) второй вызов и усреднение.

## Размер выборки и пороги
- Персонажи: 10 книг × 3 персонажа = 30 персонажей; консистентность 4 пробы + приветствие (150 вызовов чата + 150 судьи), современный мир 10 проб (300 + 300), спойлеры 2 пробы (60 + 60). Пороги: CH-03 ≥0.90, CH-04 ≥0.90 (блокер релиза <0.80), CH-05 ≥0.90, CH-12 ≥0.90.
- Описания: все 17 книг × все персонажи (~150–300 судей) — CH-02 ≥0.90 персонажей pass, contradiction hard_fail ≤2%.
- Портреты: 30 (сэмпл) + все портреты C&P; pass ≥0.90, hard_fail ≤5%.
- Сцены: по умолчанию 15 уже опубликованных; с `--generate` 3 книги × 3 прогресса = 9 новых генераций; mean ≥3.5, доля ≥3 не ниже 0.80, hard_fail ≤0.10, стиль ≥0.85.
- Ассистент: 20 проб + 5 tool-кейсов, pass ≥0.90, tool_call присутствует в 5/5.
- Речь: все голоса реестра (≈14) + 10 STT-предложений.
- Каталог-контент: 17 книг, все chunks — 0 hard-fail по html/ссылкам.

## Бюджет
Оценка на прогон: ~700 chat-вызовов гейтвея (модель уровня gpt-5.x-mini/Giga — 1–3 $), ~800 текстовых судей на 1–2k токенов (~2–4 $), ~50 vision-судей (~1–2 $), 9 генераций сцен (~1 $), речь (~0.5 $). Итого 6–10 $ при cap `NARRA_EVAL_MAX_USD=10`; CLI ведёт `cost_usd` по `src/pricing.json` и останавливает suite при превышении. Кэш ответов гейтвея по `request_hash` в `reports/.cache/` позволяет пересчитывать судью бесплатно. PR-прогоны — только детерминированные слои (0 $).

## Отчёт
`reports/YYYY-MM-DD/<suite>.json` (записи по схеме из harness_design) + `summary.md`: таблица case_id → pass-rate/mean/hard-fail/порог/статус/Δ к прошлому прогону, топ-10 провалов с request_hash и ссылками на артефакты (портреты/сцены сохраняются в `reports/…/artifacts/`). Статус релизного gate: RL-01…RL-07 зелёные/красные.

## Ручной сценарий на симуляторе (docs/qa/narra-core-loop-manual.md)
Подготовка: `cd packages/app-expo && ./script/build_and_run.sh` (iPhone 17 Pro, Metro localhost, без туннелей); `READANY_METRO_PORT=8081 node scripts/performance/transition-probe.cjs status` → `ready:true`; запись `xcrun simctl io booted recordVideo ~/Desktop/narra-qa.mov` (остановить Ctrl+C). Ожидание по AGENTS.md: старт без RedBox, экран «Библиотека» доступен.
- M1 (OB-08) Импорт: «Библиотека» → импорт → Files → выбрать EPUB. Ожидание: русский тост об импорте, карточка с обложкой ≤5 с, повторный импорт того же файла → сообщение о дубле, второй карточки нет.

- M4 (RD-02/RD-06) 10 свайпов вперёд, 10 назад. Ожидание: каждое перелистывание ≤100 мс визуально, прогресс-% в тулбаре обновляется, возвращение на исходную страницу.
- M5 (RD-03) ☰ → оглавление → глава 3. Ожидание: шторка ≤300 мс, переход в главу, заголовок совпадает.
- M6 (RD-04/RD-07) Закладка → тост; открыть список закладок — запись есть; Aa → тёмная тема — мгновенно, позиция не сброшена.
- M7 (RD-05/OB-06) Закрыть приложение свайпом (не просто в фон), запустить заново → таб «Читалка» открывает ту же страницу ≤2 с (P3 из work order). Проверить также после чтения <5 с до закрытия (троттл).
- M8 (AU-07) Play в нижнем тулбаре → первая фраза ≤3 с, подсветка следует, пауза/резюм, блокировка экрана не прерывает, смена нарратора в настройках применяется без перезапуска.
- M9 (CH/SC/NA-06) Тап по имени героя в тексте → карточка (портрет, черты) → «Поговорить» → приветствие в характере ≤8 с; спросить «что такое интернет?» — ответ без знания понятия (CH-04). «✦ Показать сцену» → «Рисуем сцену… 20–60 секунд» → картинка в тексте с подписью, ↻ перерисовывает; таб чата с Наррой → стрим ≤3 с, клавиатура не перекрывает поле; свайп между табами не срабатывает как тап.
- M10 (CH-06/CH-07) Герой, появляющийся позже, показан тизером «Появится в главе N»; долистать до главы → герой открывается; в карточке после следующих глав появляются новые пункты профиля.
